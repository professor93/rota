# Phase 6: the web page additions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

This phase changes only the page that `rota serve` already serves at `/terminal`. The one-time login page, `rota login --web`, is phase 3's and is not here.

**Goal:** `/terminal` becomes where held sessions are reached from a browser or a phone. It gets a list of named sessions with their status, in the manner of Remote Control, and a stable `/terminal#<id>` link for each one. It gets New with the TUI's fields, explicit Fit with pan and scale, and a composer and quick keys for phones. Resume and Move arrive once phase 4 serves them.

**Architecture:** The page's own script moves out of `api/terminal.html` into small classic scripts under `/assets/term/`, one file per region. They share one global scope, as the inline script does now. That lets seven tasks change seven files at once, and one Node kit drives every file in tests. The server gains one WebSocket frame (`state`), one description field (`waiting_for`) and versioned asset URLs. It gains no exported Go name and no dependency. Phase 4's Resume and Move, phase 5's event stream and phase 3's palette plug into stubs named here.

**Tech Stack:** Go 1.27 with only the standard library in the root. Plain browser JavaScript with no build step. xterm.js 5.5.0 and addon-fit 0.10.0 stay vendored, and @xterm/addon-unicode11 0.8.0 joins them. Node 26 runs the page's tests, locally and in CI (`ci.yml` already sets it up).

**Spec:** `docs/superpowers/specs/2026-11-01-tui-daemon-ssh-design.md`. Read section 4 (Sessions), section 12 (Web), and section 13's "The terminal", "Sending and attention" and "Files and reach". Then read "The owner's answers" and "Calls made without asking", which bind this plan. Phase 1's plan, `docs/superpowers/plans/2026-11-06-phase-1-holder-daemon.md`, built the server side these tasks stand on. Its Tasks 6 to 8 matter most here: the description fields, the `repaint` and `fit` frames and the send route.

## Review Focus

1. **A phone that sleeps mid-send.** The fetch rejects, or never answers before the tab is frozen. The message must not be sent a second time by itself. The draft must stay, and the page must say honestly that it may not have gone. Test: Task 8, `a send the network loses is not sent again`.
2. **A stray tap.** This means Fit, a quick key or Send while another person holds the keyboard, or Fit while others are watching. Nothing may be typed or resized without an act that the person is allowed to make and has confirmed. Tests: Task 7, `a Fit under another person's keyboard, or declined, sends nothing`, and Task 8, `a quick key under another person's keyboard types nothing`.
3. **A stopped, foreign or unreachable session opened from the list or from a link.** There must be no reconnect loop against a 409, and the reason must be shown. Test: Task 3, `a stopped or foreign session opens no socket, however long the page waits`.
4. **A hostile or stale `#<id>` link, and a name or title that holds markup.** Nothing is rendered as HTML, and an unknown id says so. Tests: Task 4, `a hostile link and a name with markup stay text`, and Task 5, `a title with markup stays text`.
5. **Degenerate sizes.** `propose()` may return null because the container is hidden. A session may be 1000 columns wide, or Fit may be asked for 0×0. The result must be no NaN, a clamped font, and a fit bounded by the server. Test: Task 7, `degenerate sizes`.

## Rulings

Where the spec is silent, these are the plan's calls. Each says what, why, and the cost if it is wrong.

1. **The page's script moves into files under `/assets/term/`**, one per region, loaded in a fixed order. *Why:* seven tasks can work at once, and no file grows past 300 lines. *Cost:* about sixteen more requests on a first load, cached as immutable after that.
2. **Every asset URL in both pages carries `?v=<version>`**, stamped by the server. *Why:* both pages now load `page.js` and `page.css` with no query, under a year-long immutable cache, so a browser keeps the old script after an upgrade. *Cost:* none.
3. **The terminal page's policy drops `'unsafe-inline'` from `script-src`**, since it has no inline script left. The playground's policy is unchanged. *Cost:* a later inline script is blocked, which a test catches.
4. **Docs are written once, in Task 10, for Tasks 1 to 9**, and Tasks 11 to 14 add their own. *Why:* `docs/reference.md` is one file, and seven tasks at once would collide in it. *Cost:* inside the `phase-6` branch, the manual lags the page until Task 10 lands.
5. **A held session pushes `state` frames** after `hello` and whenever its status, `waiting_for`, title or name changes. *Why:* the quick keys must come forward when Claude Code asks for a permission, not up to 10 s later on the next poll, and phase 5's stream may not be there. *Cost:* one more frame type in the protocol.
6. **The list's order is fixed.** Live sessions come first, newest started first, then stopped ones, newest stopped first. A status change never moves a row. *Why:* the server's order today is a Go map's, so rows shuffle on every poll, and a row moving under a finger is a mis-tap. *Cost:* a session that needs you may sit below the fold. The header count and the tab title's `(N)` make up for that.
7. **Stopped sessions are a group with a Hide toggle**, remembered per device. *Cost:* a cluttered list until it is hidden.
8. **At 1040 px or narrower, the page shows either the list or the open session**, with **← Sessions** to go back. *Why:* in the stacked layout of today, a phone scrolls past the whole list to reach the terminal. *Cost:* none on wide screens.
9. **`/terminal#<id>`** is kept with `history.replaceState`. A hash counts only when it is 16 hex characters or the id of a listed terminal. *Cost:* the back button does not step through sessions.
10. **The credential kind is derived from `/v1/accounts`**, unless phase 4's `account.credential` is present. `credential: "apikey"` reads as *API key*, a `long_until` still in the future as *long token*, and anything else as *login*. *Why:* a claude account with a valid long token launches on it (`lib/claudehome.go:192`). *Cost:* wrong only inside the long token's last 24 hours (`lib.LongLeeway`).
11. **New** shows the label as **Name**. Its Worktree option appends `--worktree` to the arguments, offered only for a claude account chosen by id. *Why:* the spec says rota adds nothing of its own, and a rotation might choose a codex account. New sends no size, so the server's 80×24 applies until a Fit. *Cost:* a new session from a phone starts at 80×24.
12. **A held session is never fitted by itself.** It is drawn at the session's size and scaled to the window's width by font size, from 13 px down to 7 px; the rest pans. A per-device toggle shows actual size instead. Fit sends `claim` where needed, then `resize` with `fit` at the 13 px size, and asks first when others are watching. Terminals that are not held keep today's auto-fit. *Cost:* small text on a phone until Fit is pressed.
13. **The composer is for held sessions only.** It sends through `POST /v1/terminals/{id}/messages`, so the holder's readiness wait, bracketed paste and separate Enter apply. Enter makes a new line, and Ctrl+Enter or ⌘+Enter sends unless an IME is composing. Trailing whitespace is trimmed. Drafts are kept in memory per session and never stored. Nothing is retried by itself. **Send anyway** appears only after a `waiting` refusal. *Cost:* a terminal that is not held has no composer.
14. **Quick keys** send the bytes of Task 8's table. The arrows follow the CLI's cursor-key mode. A free keyboard is claimed first. Nothing is sent under another person's keyboard. *Cost:* none.
15. **The dock shows by `(hover:none) and (pointer:coarse)`** unless the strip's **Composer** toggle has said otherwise on that device (`rota.dock`). It is hidden for watchers and for ended sessions. *Cost:* a touch laptop does not get it until it is asked for.
16. **`@xterm/addon-unicode11` 0.8.0 is vendored and active**, which carries out phase 1's ruling on the T2 spike. *Cost:* one 10 KB file.
17. **Forgetting a stopped session is not on the web in phase 6.** It belongs to the TUI (`x`). *Cost:* stopped sessions stay listed for `keep_stopped` unless they are hidden.
18. **A held session's button reads Stop**, and its confirmation says a worktree is left alone. Other terminals keep Kill. *Cost:* none.
19. **Phase 5's stream is read with `fetch` and a stream reader**, not `EventSource`, so a bearer token travels in a header and never in a URL. Polling stays on. *Cost:* about 30 lines that EventSource would have saved.

## For the owner

**1. Remote Control from the page (security-sensitive).** The spec's web New has "the same fields as the TUI", and Remote Control is one of them. Phase 1 takes `remote_control` on `POST /v1/terminals` only over `ctl.sock` (`api/terminals.go:157-166`, *remote_control is taken only over the control socket*). The page reaches the daemon over TCP, so today the page cannot offer it.

While planning, I found that a control principal on TCP can already turn the account's setting on with `PATCH /v1/accounts/{id}` `{"remote_control":true}`. It can also pass a raw `--remote-control` in `args`, which skips `store.ReadyRemoteControl`, the check that keeps Remote Control from acting as the wrong identity.

The options:
- **A.** Any control principal on TCP may send `remote_control`, as `PATCH` already lets them. Every use is logged by name. **Recommended**, together with **F**.
- **B.** Only `[[users]]` people with role control may send it. A bearer token or an invite still gets 403.
- **C.** Only when `server.toml` opts in with `[terminal] remote_control = true`. It is off by default.
- **D.** It stays control-socket only, and the web New has no Remote Control at all.
- **E.** It stays control-socket only, and the form shows the option disabled with the line *start it from this machine: rota run <id> --detach --remote-control*.
- **F.** Separately, and on its own yes or no: refuse a raw `--remote-control` among `args` from a TCP principal, pointing to `remote_control`. Then Remote Control can only start the readied way. **Recommended: yes.**

Task 14 does whichever the owner picks, and nothing else waits on it.

**The quick keys**, `#dock_keys`. Each button carries its `data-key`:

| `data-key` | label | bytes |
|---|---|---|
| `1` `2` `3` | `1` `2` `3` | `1` `2` `3` |
| `esc` | `Esc` | `\x1b` |
| `enter` | `⏎` (aria-label `Enter`) | `\r` |
| `tab` | `Tab` | `\t` |
| `up` `down` `left` `right` | `↑` `↓` `←` `→` (aria-labels `Up` `Down` `Left` `Right`) | `\x1b[A` `\x1b[B` `\x1b[D` `\x1b[C`, or `\x1bOA` and so on when `appCursor` |
| `ctrl-c` | `^C` (aria-label `Ctrl-C`) | `\x03` |

`termSendKey(name)` sends the bytes as one binary frame when `termIHold()`. When the keyboard is free, it sends `{"type":"claim"}` first and then the bytes. When `termHolder` is someone else, it sends nothing, flashes, and says `` `${termHolder} holds the keyboard` ``.
