## rota 1.2.0

### Changed for people coming from 1.1.0

- **Every claude launch prefers a long-lived token once the account has one.** Nothing has one until you ask for it with `rota login --long`, so nothing changes by itself; from the moment one is stored, `rota run`, the interactive handover, a server request and a terminal all use it instead of the eight-hour access token. A launch that has one does not refresh first, and an account whose ordinary login has died still runs **when you name it** — the rotation still skips it. `rota set <id> --long forget` throws the token away.
- **A mirror entry that stopped being a link is named at launch.** Claude Code writes some files by renaming a temporary file over the path, which replaces rota's symlink with a real file: that entry then reads and writes a fork of its own while your copy is never touched again. Every such entry is now named in a warning on the next launch, with the directory it was meant to link into. Nothing is moved or replaced — move it aside yourself and the launch after that links it again.
- **`rota serve --help` no longer prints the live token.** `--token`'s default used to be the value of `ROTA_TOKEN`, which `flag`'s own help printed. The default is empty now and the environment is read afterwards, so the help says `(default: ROTA_TOKEN)` and nothing else.
- **`rota serve` reads `$ROTA_HOME/server.toml` (or `~/.rota/server.toml`) when there is one.** There was no such file before 1.2.0, so a server that has not been given one behaves exactly as it did. A file that exists must belong to its owner alone — rota refuses to start otherwise, and says the `chmod` that fixes it.
- `GET /v1/health` is new and on by default: unauthenticated, never rate-limited, `{"ok":true}` and nothing else.
- `rota list` says one line about a long-lived token within thirty days of its end, and one more if it has lapsed. `--json` and `GET /v1/accounts` carry `long_until`.

### A token that outlives the window

Eight hours is fine for a command and wrong for a window left open overnight, a daemon, or one long session: Claude Code keeps the token it was started with and refuses by design to adopt another after a 401, so refreshing rota's own copy reaches nothing.

- `rota login --long` begins a login for a year-long token; approve it in the browser as the account it is for, and finish it with `rota login <login-id> <code>` as usual.
- The exchange says who approved, and that identity must match an account rota already holds. Approving as anybody else is refused and nothing is stored.
- The token is inference-only by the provider's own design: usage, rotation and identity stay with the ordinary login, which is the one that can read them. It is a second key to the same door, not a replacement for `rota login claude`.
- Over HTTP: `POST /v1/login {"long":true}`, `POST /v1/login/{id}` answering `{"status":"long","long_until":"…"}`, `long_until` on every account view, and `PATCH /v1/accounts/{id} {"long":"forget"}`.

### One file for the server

`rota serve` can be written down once instead of typed every time. `--config PATH` reads another file; `--print-config` prints the whole schema as TOML with a comment on each line saying where its value came from, and exits.

- `[server]`, `[tls]`, `[auth]`, `[routes]`, `[runs]`, `[store]` and `[terminal]`, plus `[[users]]` and `[[tokens]]`.
- A flag beats the environment, the environment beats the file, and the file beats the default. A flag counts only when it was actually typed.
- The file may hold the bearer token and derived passwords, so on unix it must be mode `0600`.
- The parser is strict: a key, a section or a type it does not know is refused by name rather than ignored.
- No secret is ever printed — `--print-config` writes `"(set)"` — so its output can be pasted where the file itself could not.
- `docs/server.toml` is the whole schema at its defaults, and a test insists it loads back equal to them.

### Who is asking, and what they may do

Every request is now made by a **principal**: a name for the log, a role, and how it arrived.

- Two roles and no third. `watch` may read everything and change nothing; `control` may do anything this server does.
- One table in the code maps route to role, and a test compares it against the routes actually registered.
- `[[users]]` are people who may sign in on the page; sessions are a `rota_session` cookie, `HttpOnly`, `SameSite=Strict`, expiring at `auth.session_ttl`, held in memory and gone when the server stops. `[[tokens]]` are further bearer tokens, each with a role, stored as SHA-256 only.
- `rota serve passwd <name>`, `rota serve token <name>` and `rota serve invite` print what to paste or ask a running server for a link. rota never writes the file itself.
- `POST /v1/invites` makes a single-use link that signs somebody in as a watcher; `GET /invite/{code}` spends it.
- `GET /v1/health` is its own route group, so a server with its page switched off still answers a watchdog.

### A terminal on the server

With `[routes] terminal = true`, the server holds terminals: an account's CLI on a pseudo-terminal that outlives the browser tab.

- `GET`, `POST` and `DELETE` under `/v1/terminals`, and `GET /v1/terminals/{id}/ws` to attach. Binary frames are the terminal's bytes; text frames are documents.
- Several people may watch one terminal; exactly one of them at a time holds the keyboard, with `claim`, `release`, `grant`, `deny` and a force that only works ten seconds after an unanswered ask.
- `[terminal]` sets `shell`, `max_sessions`, `scrollback_bytes`, `idle_timeout`, `record`, `record_max_bytes` and `share`.
- Replay is by absolute byte offset: `?since=N`, and a `gap` frame when N is older than the scrollback. A reader that falls behind is closed with `1013` and reattaches.
- The audit log is always on and never carries a keystroke or a line of output. With `record = true`, what a terminal printed — never what was typed — is kept under `<store>/terminals/`.

### The terminal page

- `GET /terminal` is its own page beside `/playground`, not a tab inside it. A server may serve either without the other.
- Both pages share `/assets/page.css` and `/assets/page.js` — one palette, one header, one sign-in — and each links to the other where the other is served.
- The emulator is xterm.js 5.5.0 and addon-fit 0.10.0, carried in the binary and served from `/assets/xterm/`. Nothing is fetched from another host at run time. `api/assets/xterm/README` records the versions, the registry's integrity strings and the SHA-256 of every vendored file, and a test recomputes them from what is embedded.
- `.gitattributes` marks those files so a checkout on any platform embeds the bytes the checksums describe.

### Sharing the terminal you are sitting at

`rota run <id> --share` opens the account's CLI where you are, as it always did, and offers the same session to a rota server on this machine so it can be watched — or typed into — from the terminal page.

- `--share=watch` offers it to be read and never typed into, whatever role the person on the page has. `--label` names it in the listing.
- The link is a unix socket at `<store>/terminals/share.sock`, mode `0600` inside a `0700` directory: who may share a terminal is decided by the filesystem, so there is no second secret.
- Sharing never blocks or slows the terminal you are at. What the CLI prints is written to your screen first and offered to the server afterwards, into a bounded queue that drops rather than waits; dropped bytes are counted and announced to whoever is watching as a `gap`.
- On the page it is a terminal like any other, `kind: "shared"`, except that its size follows the window it was started in and the person at that window can always type.

### Platforms

Linux first, macOS second. The terminal — the server's own and `rota run --share` alike — needs a pseudo-terminal, so it runs on Linux and macOS only: a server configured for one anywhere else refuses to start and names the platform, and `--share` is refused by name. Everything else builds and runs on Windows, and Windows binaries are in the release.

### Security

A `control` sign-in on the terminal runs commands on this machine, as the user the server runs as. That is not an API over accounts and runs; it is a shell prompt. `watch` exists so that showing somebody what is happening does not mean handing them the machine.

The terminal is off in the defaults — the one route group that is — and with it on, a listen address that is not the loopback requires `tls.cert` and `tls.key`. rota refuses to start rather than warning, because a sign-in that travels in clear text is a sign-in given away, and the cost of being wrong here is the machine.

A year-long token sitting in `~/.rota/accounts.json` is worth far more to a thief than an eight-hour one. If that file ever leaves your machine, revoke the token from the provider's account settings — and treat the file the way you treat a private key.
