## rota 1.3.1

### Changed for people coming from 1.3.0

- **A home whose daemon has given up on its login is refreshed, and nobody has to log in.** Claude Code's daemon refreshes the login itself, and now and then the refresh fails, on a plain `~/.claude` as much as in a home of rota's. When the access token had run out by then, the sessions the daemon hosts said `Login expired · Please run /login` and it waited for a newer login to appear, while rota, seeing something alive in the home, waited for the daemon to go away. An account could sit like that for days on a login that was alive the whole time. Now a listing, maintenance or a launch refreshes such a home, writes the login in under the running daemon, and says so in one line.
- **`rota list` says when a login ends.** In its last three days the STATUS column reads `ok (login ends in 2d)`, and `ok (login ended 3h ago)` once it is over, because sessions that outlive a login stop making progress and cannot recover by themselves. The line under the table in the last five days stays, for `--short`, and says what to do.
- **A dead account always says why.** A login Claude Code cleared now reads `Claude Code cleared the login in its home after the provider refused its refresh token`, and an account marked dead by a rota that kept no reason says that much instead of nothing, in `rota list`, `--json` and `GET /v1/accounts`.
- **A CLI is asked to stop before it is killed.** On Linux and macOS a cancelled run, a timeout or a run over a bound sends SIGTERM to the CLI's process group and SIGKILL three seconds later to whatever has not gone. Claude Code rotates its refresh token, and a process killed between the provider accepting a refresh and the store saving it loses the login for everything in its home. A CLI that stops when asked costs nothing; one that does not holds its run for those three seconds. Windows is unchanged.
- **More inherited variables are dropped.** `CLAUDE_CODE_SIMPLE`, `ANTHROPIC_PROFILE`, `CLAUDE_CODE_USE_FOUNDRY`, `CLAUDE_CODE_USE_MANTLE`, `CLAUDE_CODE_USE_ANTHROPIC_AWS` and `CLAUDE_CODE_OAUTH_REFRESH_TOKEN` no longer reach a claude account's CLI, on any route: each would change how it signs in, or stop it reading its login at all.
- **On macOS a credential file newer than the keychain item is the login.** Claude Code keeps the login in the file when the keychain refuses a write, so the file is not always the stale copy. rota reads the newer of the two; in a quiet home a file no newer than the item is removed as before, and a newer one stays and the older item goes instead, so Claude Code reads it too.

### What to do

Nothing. An account stuck on `Login expired` with its daemon still running comes back the next time you list it or launch it. A login the provider really did refuse stays dead and says so: `rota login`, or `/login` inside one of its windows.

### A stranded home

- It takes all of this: rota keeps the login in that home, the account is alive and out of the hold, the home holds the account's own current login, the store's lock is held, the daemon and the sessions it hosts are all that runs there, `daemon-auth-status.json` says `auth_required` about the token that ran out, and that token truly expired at least ten minutes ago.
- The status file outlives recovery, so on its own it means nothing: with a good token rota does nothing, and a file older than the token that ran out is about some earlier token.
- A window open beside the daemon is a refresher that has not given up, and the home stays its own, as does everything else about the rule that rota leaves a live home alone.
- While it refreshes and writes, rota holds Claude Code's own refresh lock, `.oauth_refresh.lock` in the home, because the daemon's re-check goes on trying by itself. A lock somebody holds leaves this look to them, and the home is read again once rota has it.
- A refusal goes as any refusal does: the home is read again first, a sibling's login is taken, and otherwise the account is dead and its token never presented again. A refresh that does not get through changes nothing, and a launch joins the home as it always did.
- A store whose lock was released rotates nothing, here as everywhere.

### For the SDK

- `Account.WhyDead` is why an account needs a login, in words for a person, and `Account.StagedCurrent` whether its home holds its current login. `wire.LoginStatus` and `wire.LoginClose` are what the STATUS column says about a login's end, and when.
- `Run` and `Start` stop a CLI as above when their context is cancelled, and return once it has gone, at most three seconds later than they used to.
